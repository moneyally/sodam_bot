# 🎧 자동선곡(라디오) 2.0 — 방 재생 기록 기반 선곡 설계

2026-11-20 오너 아이디어: "지니뮤직처럼 대기열 끝나면 같은 가수·비슷한 장르로 자동 이어틀기, 빠른 선곡."
리서치 에이전트 3갈래(한국 서비스 / 무료 API / 알고리즘) + 조사 종합.

## 조사 결론 (왜 이 설계인가)
- **지니·멜론·FLO·벅스 = 공개 API 없음.** 수백만 유저 청취로그 협업필터링이라 봇이 자체 재현 불가 → 그대로 못 베낌.
- **의외의 핵심**: 세션 추천 학계 벤치마크(Jannach·Ludewig, RecSys 2017·2019)에서 **동시출현·순차규칙(SR) 같은 단순 카운트가 GRU4Rec·GNN 신경망을 대부분 이기고 CPU로 즉시** 된다. GPU 불필요.
- **외부 추천 API는 리스크**: Last.fm 은 상업 판매면 별도 계약 필수(위반 리스크), Spotify 는 추천 엔드포인트 폐기(2024-11~), Deezer 만 무료·깨끗하나 한국 커버리지 약함.
- → **결론: 외부 API 없이, 이 방이 실제로 이어 튼 기록(`music_queue`)으로 내부 선곡.** 공짜·즉시·한국가요 최적(이 방 취향 그대로)·상업리스크 0. 유튜브 믹스는 폴백.

## 구현 (`sodam/voice/autodj.py`)
**별도 학습 표·훅 없음** — `music_queue`(이미 쌓이는 재생 기록)에서 그때그때 계산 → 버그 표면 최소. `pick()` 하나.

신호를 0~1 정규화해 가중합 (이 방이 우선, 다른 방은 보조):
1. **방 순차규칙(SR, W_SR=1.0)**: 이 방에서 씨드 곡 다음에(거리 d≤LOOKBACK=3) 온 곡을 1/d 로 가중. "이 방이 이 곡 뒤에 트는 곡."
2. **방 인기도(W_POP=0.4)**: 이 방에서 많이 튼 곡.
3. **다른 방 순차규칙(W_GSR=0.5)**: 다른 방들에서 씨드 곡 다음에 온 곡 — 전역 기록(GLOBAL_MAX=5000) 에서 **방 경계로 끊어** 셈(방이 섞여 가짜 전이 안 생기게). 새·얇은 방 콜드스타트에 특히 도움.
4. **다른 방 인기도(W_GPOP=0.25)**: 다른 방들에서 많이 튼 곡.
5. **같은 가수 보너스(W_ARTIST=0.5)**: 제목에서 가수 파싱(`'가수 - 곡'`), 씨드와 같으면 가점. 단 **이 방 최근 ARTIST_RUN=2곡이 같은 가수면 보너스 끔**(다양성, 같은 가수 3연속 방지).

제외: 씨드 곡 + 최근 15곡(`recent_keys`, song_key 기준) → 바로 반복 안 됨. 재생 ID 없는 후보 제외.
방+전역 기록 합이 MIN_HISTORY=4 미만이거나 후보가 없으면 `None` → 호출부가 유튜브 믹스로 폴백.

## 통합 (`music.py Player._autoplay`)
대기열 비면: ① `autodj.pick`(방 기록, 외부 호출 0, 즉시) → ② 없으면 기존 유튜브 RD믹스(`source.related`). 최근 15곡만 반복 방지(seen_v 50개 전체를 넘기면 되살릴 과거 곡까지 빠져서 recent_keys 로만).

## 왜 좋나
- **공짜**(외부 API 0)·**즉시**(유튜브는 매번 네트워크, SR 은 DB 조회라 더 빠름)·**GPU 0**·**상업리스크 0**.
- **이 방 취향 그대로** — 업자방마다 미는 노래가 기록에 반영됨.
- 유튜브 RD믹스의 'unviewable'·불안정을 내부 추천으로 대체(폴백으론 유지).

## 미착수 (2단계, 지금은 안 함 — 조사상 가성비 낮음)
- **같은 가수 '새 곡' 외부 검색**(지금은 기록 속 같은 가수 재생 + 유튜브 폴백이 담당). Deezer `/artist/{id}/related`(무료·키 없음, 단 검색 시 `nb_fan` 최대 아티스트 골라야 가짜 업로더 회피).
