### 지금까지 (전부 로컬 PG16 로 실측, 매 조각 뮤테이션 + SQLite 회귀 0)
- **아키텍처**: `sodam/pgbackend.py` = 동기 psycopg 를 전용 스레드 1개에서 (aiosqlite 구조 흉내). `db.atomic()` 콜백 144개를
  **안 고치고** 그대로 삼 (`_execute`/`_conn` + SAVEPOINT 흉내). `tests/test_pgbackend.py`(PG_TEST=1 opt-in 로컬 PG, 15개 + 뮤테이션).
- **db.py 통합**: `DB(path, pg_dsn=)` + `DB_BACKEND=pg` 면 `_open_pg()`(스키마·`_migrate_pg`(information_schema)·`_backfill_fts`·pg_trgm/vector 확장·GIN).
  SQLite 경로는 **조기 반환 뒤 한 글자도 안 바뀜**(전체 2256 시험 0 실패로 확인). `hour_sql`/`hour_offset_sql`(한국시 집계 방언), `_fts_where`(검색).
- **translate 가 체계적으로 처리하는 SQLite→PG 방언 (전부 PG 전용, SQLite 무관)**:
  `?`→`%s`(**문자열 속 '?'는 글자로 보존**)·`%`→`%%`·`INSERT OR IGNORE`→ON CONFLICT DO NOTHING·`INSERT OR REPLACE`→**ON CONFLICT DO UPDATE(PK introspect 자동)**·
  `INTEGER PRIMARY KEY (AUTOINCREMENT)`→`GENERATED BY DEFAULT AS IDENTITY`(AUTOINCREMENT 없어도)·`strftime('%s','now')`→extract·`char()`→chr·`instr()`→strpos·
  스칼라 `MAX/MIN(a,b)`→GREATEST/LEAST(괄호균형)·`SUM(불리언)`→`SUM((…)::int)`·`COLLATE NOCASE`→`LOWER()`·`PRAGMA`→no-op·
  `IS 값`→`IS NOT DISTINCT FROM`(널세이프 등호)·`json_extract`→`#>>`·**`LIKE`→`ILIKE`(대소문자 무시 보존 — 조용한 버그 방지)**·
  `UPDATE OR IGNORE`→PK로 충돌 행만 건너뛰기(migrate_chat)·`ON CONFLICT DO UPDATE SET col=col+…`→표이름 수식(`SyncConn._qualify_update`)·
  `_Cur.__iter__`(커서 직접 순회)·FTS5 가상표→평범표+pg_trgm·sqlite-vec→pgvector.
- **PG 에서 통과 확인된 모듈**(DB_BACKEND=pg + 하네스): 💰 billing 15/15(결제·구독연장)·budget·casino(돈 로직)·memory 4/4·chat_min_chars·chatrank 26/28·
  insight·fedban·members·free·away·lottery·sports_picks·reports·casino_event·moderation·subgate·abuse·cleanup·onboard·karma·notes·autoreply·protect·ownerlock·summon·rates·
  scamring·anomaly 23/24·mediastore 8/9·opsdesk 24/25·spamshield 34/35·news 32/33. **persist.claim(전역 dedup) PG 정상 확인.**
- **🔍 SQLite 전용 문법 grep 전수 감사 결과 (안 놓치려고)**: group_concat·IFNULL·GLOB·printf·json_set/object/array·RANDOM()·date()/time()/datetime()/julianday·
  typeof/hex/quote/randomblob·last_insert_rowid·total_changes·WITHOUT ROWID = **전부 0건**. rowid 참조는 **전부 내가 만든 explicit 컬럼**(fts·msg_vec) — 암묵 rowid 의존 **없음**.

### ⚠️ 아직 안 된 것 — 다음 세션이 꼭 할 것 (놓치면 사업 깨짐)
1. **`ATTACH DATABASE`(clone_migrate.py:50)** — 클론 방 이관이 raw sqlite3 + ATTACH 로 두 .db 복사. **PG 엔 ATTACH 없음** → PG 에선 작동 안 함.
   클론을 PG 로 옮기기 전에 **반드시 재작성**(postgres_fdw 또는 앱단에서 main→clone 읽어쓰기, 또는 dump/restore). Phase 2 클론 이관의 전제.
2. **per-query 꼬리 (PG 에선 에러로 터지니 조용한 버그 아님 — DB_BACKEND=pg 전체 시험이 다 찾아줌)**: `SELECT DISTINCT … ORDER BY`(SELECT 목록에 ORDER BY 컬럼 추가) ·
   남은 `GROUP BY` bare 컬럼(집계 안 한 컬럼을 GROUP BY 에 추가, SQLite 무해). 이미 여러 개 고침(top_chatters·reply_stats·away·lottery·sports_picks·casino_event).
   **찾는 법**: `DB_BACKEND=pg PG_TEST_DSN="dbname=sodam_harness" ~/venv/bin/python tests/run_all.py <모듈>` 돌려 `psycopg.errors.GroupingError`/`InvalidColumnReference` 나오는 컬럼을 그대로 GROUP BY/SELECT 에 추가.
3. **테스트 전용 sqlite 문법** (PG 하네스에서만 문제, 제품 아님): 테스트가 `CREATE TRIGGER … WHEN NEW.…` 로 오류 흉내(name_key·memory), `.db 직접 읽는 도구`(usage_report), 클론이 `dbname=sodam_main` 여는 것 — PG 용으로 바꾸거나 skip.
4. **⚠️ PG 쿼리 지연 실측(실서버 VPS)**: dev 컨테이너선 게임 명령 1회 ~1s(쿼리 수십 개 × 스레드홉+소켓). **VPS(로컬 소켓·튜닝)에서 실측 필수** — 느리면 게임 핫패스 쿼리 묶기. go/no-go 숫자.
5. **조용한 behavior 차이 더 점검**(에러 안 나서 위험): ORDER BY 한글 정렬 순서(SQLite BINARY vs PG locale) — 순위/목록 순서 바뀔 수 있음, 실측 필요. (LIKE 대소문자는 ILIKE 로 이미 잡음.)

### Phase(단계)
- **1단계(코드, 거의 끝)**: 위. 남은 건 per-query 꼬리 + ATTACH 재작성 + behavior 점검.
- **2단계(데이터 이관, VPS)**: 제일 작은 클론부터 `pgloader` 로 복사 → 표별 행수·`SUM(points)` 대조 → 며칠 운영 → 본체 맨 마지막. 돈 표는 점검모드(쓰기 멈춤)로. SQLite 백업 수주 보관.
- **롤백**: `DB_BACKEND=sqlite` 로 1초. 이관 중 SQLite 는 안 지우고 안 멈춤.

### 안전 규칙 (어기면 사업 깨짐)
- 기존 SQLite 절대 안 지움 · 클론 하나로 완전 검증 후 본체 맨 마지막 · 표마다 행수·합계 대조 · 돈 표는 점검모드 복사 · env 토글 1초 롤백 · 한 번에 두 단계 금지.
