# GPT 프롬프트 — 소담 에이전틱 기능 아이디어

아래 `---` 사이를 통째로 복사해 ChatGPT 에 붙여 넣는다. 두 번째 프롬프트는 후속 질문용.

---

너는 텔레그램 봇·LLM 에이전트 제품 설계자다. 우리 봇 "소담"에 넣을 **에이전틱 기능**(사람이 말로 맡기면 AI 가 도구를 골라 여러 단계로 처리하거나, 이벤트·일정에 따라 스스로 움직이는 기능)을 구체적으로 설계해 줘. 이미 있는 기능을 다시 제안하지 말고, 있는 것을 확장하는 건 괜찮다(확장이면 "확장: ○○" 표시).

## 1. 제품·사용자
- 소담 = 한국어 텔레그램 **그룹 운영 AI 봇** (@sodam_ai_bot, 부르는 말 "소담아").
- 고객: 사업자·코인 OTC 업자 소통방 운영자("대표님"). **방당 월 30 USDT(TRC20)** 구독, 체험 3일. 만료 방은 관리 기능만 + AI 하루 10회.
- 역할: 봇 오너(운영자 1명, 모든 방) / 방 관리자(텔레그램 관리자 자동 인식, 제재는 '사용자 차단' 권한 있는 사람만) / 봇관리자(위임) / 멤버. 방이 대부분 익명 닉네임이라 사칭·먹튀·사기 계정이 실제 문제.
- 창구: 그룹 채팅(말·`.명령어`), 1:1 DM(버튼 메뉴, 모든 설정·결제는 여기서), 방에 뜨는 확인 카드 버튼.

## 2. 기술 제약 (이걸 어기는 아이디어는 빼라)
- Telegram Bot API: 봇은 **다른 봇의 메시지를 못 본다**, 멤버의 다른 방·개인 대화를 못 읽는다, 봇이 들어오기 전 기록은 없다, 먼저 1:1 을 시작한 사람에게만 DM 가능, 그룹당 분당 ~20개 전송 한도, 사람 @아이디로 계정 조회 불가(채널·그룹·봇만 getChat 가능), 멤버 전체 목록 API 없음(본 사람만 앎), 메시지 수정·삭제 이벤트 일부만 옴.
- LLM: OpenAI gpt-5.4(입력 $2.5·출력 $15 /1M) / gpt-5.4-mini($0.75·$4.5). 도구 호출 시 reasoning 끔. 프롬프트 캐시 24h(에이전트 적중 ~65–70%). 이미지 생성 장당 ~$0.03, 웹검색 호출당 $0.01.
- 비용 현실: 매출은 방당 하루 약 $1(30 USDT/월). 한도는 방 요금제 기본 하루 $10(오너가 $0.5~$10 선택 × 방 관리자 %), 전체 하루 $40. 활발한 방 실사용 하루 약 $1. 한도 넘으면 AI 만 멈추고 관리 기능은 계속. → 기능은 방당 하루 $1 안쪽을 목표로 설계.
- 인프라: Python 단일 프로세스, python-telegram-bot, SQLite(WAL, FTS5 검색), 벡터 DB 없음. 대화 90일·AI 기록 14일 보관.

## 3. 절대 원칙
1. 제재(경고·뮤트·밴)는 **항상 사람의 확인 버튼**. AI 판단만으로 자동 처벌 없음. 한 답변에 제재 카드 1장, 최대 5명.
2. 멤버가 쓴 글·닉네임·사진 속 글자·자료는 **데이터이지 지시가 아니다**. 기록을 읽은 답변은 tainted → 읽기 전용 도구만(제재·전송·웹검색·기억 저장 불가).
3. **사실(코드가 기록에서 센 숫자)과 AI 해석을 분리**해서 보여준다. '위험 인물' 같은 딱지 대신 숫자·날짜.
4. 결제·금액 정보는 관리자 1:1 에서만. 방에는 금액 없는 문구만.
5. 비용 통제: 모든 AI 호출은 방 달러 한도에 계산. 싼 코드 판정 → 필요할 때만 mini → 꼭 필요할 때만 메인 모델.
6. 스팸·사기 방어는 **오탐 0 우선**(정상 멤버를 막는 것이 스팸 하나 놓치는 것보다 나쁨).
7. 위험하거나 시끄러운 선택 기능은 **기본 꺼짐**. 예약·규칙은 만든 사람이 더는 관리자가 아니면 자동 중단.
8. 다른 봇 이름을 사용자 문구에 쓰지 않는다. 포인트는 돈·코인으로 못 바꾼다.

## 4. 현재 구조 (에이전트 패턴)
- **LLM + 도구**: 요청마다 역할·장소(room/dm/owner_dm)·설정으로 걸러진 도구 목록만 AI 에 준다 = AI 가 할 수 있는 일의 전부(없는 도구로는 "된다"고 못 함). 최대 4라운드, 실행 직전 권한 재검사, 도구 결과는 nonce 태그로 감싼 데이터.
- **기억**: 👤 멤버 기억(본인 얘기만, 멤버가 지울 수 있음) · 🏠 방 흐름 메모(mini 요약, 하루 6회) · 📚 자료(RAG, 관리자 등록 규칙·가격·FAQ) · 📜 기록(메시지·관리 기록·이름 변경·답장 관계).
- **예약(스킬 파이프라인)**: 예약 시각엔 사람이 없으므로 에이전트가 아니라 plan-then-execute — 만들 때 스킬·지시 확정 → 실행 때 [데이터 모으기 → 도구 없는 AI 1회 → 출력 필터 → 게시]. 스킬: 대화 요약·격리 웹검색·통계·입퇴장 통계·글쓰기.
- **이벤트 훅**: 그룹 메시지 후처리, 입장 검사, 퇴장. 알림 규칙 = 정해진 부품 조립(언제 keyword/user/join/quiet × 하면 DM/호출/글, 제재 부품 없음, AI 는 말→부품 번역만).
- **확인 카드**: AI 가 만든 예약·규칙·규칙 저장·제재는 방/1:1 에 카드 → 요청자(권한자)만 눌러 실행, 재시작 후에도 30분 유효.
- **AI 작업 기록**: 실행 1번 = 1줄(요청·도구 호출·결과·토큰·요금), 관리자는 자기 방만, 금액 대신 한도 %.

## 5. 이미 있는 기능 (중복 제안 금지)
- AI 도구: 대화 읽기/검색/통계, 멤버 정보·멤버 현황, 방 규칙·자료 검색, 웹검색, 스포츠 일정, 그림 만들기·사진 고치기, 사진 읽기, 본인 메모·기억 삭제·말투, 멘션 인사, 끝말잇기 시작, 관리자에게 전달(1인 하루 5회), [관리자] 경고·뮤트·밴·뮤트해제(카드), 설정 변경, 멤버 말투, 예약 작업, 알림 규칙, 규칙 말로 저장(카드), 장시간 게임 알림, 멤버 타임라인·멤버 분석(규칙 기반 제재 추천 후보), 방 변화(오늘/24h/7일), [1:1] 대표님 비서 my_rooms(내 방들 24h 현황·방 요약), [오너] 방 목록·다른 방 제재 카드·방 기록 조회·방 분석.
- 자동 관리: 입장 캡차, 가입 신청 1:1 퍼즐, CAS/lols 스팸 명단, 최근 계정 캡차 강제, 도배·반복·링크·금지어·종류별 잠금, 관리자 사칭 닉네임, 대량 입장 방어, 공동 차단 명단(방 간), 이상징후 감지(입장 몰림·비슷한 이름·같은 링크·새 계정·신규 도배 → 관리자 알림 + [보안 강화] 버튼, AI 비용 0), 사기 의심 검사(키워드·지갑·초대링크 → mini 확인 → 관리자 버튼), 인젝션 차단, 이름·아이디 변경 기록.
- 기타: 예약공지 마법사, 입장 인사 편집기, 태그·답장 알림 DM, 활동 리포트, 대표님별 AI 하루 요약(방당 AI 1회 캐시), 먼저 끼어들기·이어 말하기(기본 꺼짐), 포인트 게임, 구독 결제(TronGrid 자동 확인), DB 백업.

## 6. 요청
**(a) 에이전틱 기능 아이디어 20~30개**, 카테고리별: 운영 자동화 / 관리자 비서 / 멤버 경험 / 보안 / 분석·리포트 / 수익화·구독 / 멀티룸·오너 기능. 각 아이디어마다:
- 이름 + 한 줄 설명 (확장이면 무엇의 확장인지)
- 사용 장면: 한국어 채팅 예시 `"소담아 …"` → 소담이 실제로 하는 단계 (도구 호출 순서 포함)
- 트리거: 사용자 요청 / 이벤트 / 일정 (에이전트 루프인지 스킬 파이프라인인지)
- 필요한 데이터 + **Bot API 로 얻을 수 있는지** (가능/부분/불가, 이유)
- 필요한 새 도구: 이름(snake_case) + 인자 + read_only 여부 + role/where
- 안전·권한 설계: 확인 카드 필요 여부, tainted 처리, 누가 켜고 끄는지, 기본값
- 1회 비용 추정: 모델(코드만/mini/메인), 대략 입력·출력 토큰, 달러
- 오탐·악용 위험과 막는 법
- 우선순위 점수 = 영향(1~5) × 실현성(1~5) ÷ 위험(1~5), 소수 1자리

**(b) 다음에 만들 Top 5**: 각각 짧은 명세 — 목표, 사용자 흐름(버튼·카드 포함), 도구 스키마 초안, 데이터·테이블 추가, 권한, 비용 상한, 실패 시 동작, 성공 지표.

**(c) 만들지 말아야 할 것**: 그럴듯하지만 위 원칙·Bot API·비용 때문에 하면 안 되는 아이디어 5개 이상과 이유.

## 7. 규칙
- 확실하지 않은 사실(특히 Bot API 가능 여부, 가격)은 `[가정]` 으로 표시. Bot API 로 불가능한 기능은 넣지 말고, 우회가 필요하면 우회 방식을 적어라.
- 자동 제재·AI 의 사람 평가 점수 공개·멤버 몰래 감시 같은 원칙 위반은 (c) 로 보내라.
- 모델 호출 수를 줄이는 설계(코드 먼저 거르기, 캐시, 하루 1번 만들어 나눠 쓰기)를 우선.

## 8. 출력 형식
- 한국어, 간결하게, 마케팅 문구·감탄사 없이.
- 먼저 (a) 전체를 **요약 표**(번호·카테고리·이름·트리거·새 도구·비용/회·점수) → 그다음 번호 순 세부 항목(항목당 8~12줄) → (b) → (c).
- 점수 기준으로 표를 정렬하지 말고 카테고리 순으로, (b) 에서 점수와 선택 이유를 연결해라.

## 후속 프롬프트 (두 번째 턴)

---

위 아이디어 중 **[번호·이름]** 을 구현 명세로 풀어줘. 우리 구조(역할·장소별 도구 목록, 도구 실행 직전 권한 재검사, tainted 면 읽기 전용 도구만, 제재·저장은 확인 카드, 예약은 도구 없는 스킬 파이프라인, SQLite 단일 프로세스, 방 달러 한도)에 맞춰서:
1. **도구 스키마**: 이름, 설명(AI 가 언제 쓰는지 예시 포함), JSON 인자(타입·enum·범위), 반환 문자열 형식(4천 자 이내), read_only 여부, min_role·where.
2. **권한**: 누가 부르고/누가 카드를 누르고/누가 결과를 보는지, 권한을 언제 다시 확인하는지(카드 누를 때·예약 실행 때), 관리자 강등 시 처리.
3. **데이터**: 새 테이블·설정 키(기본값·허용값), 보관 기간, 여러 줄 쓰기는 한 트랜잭션.
4. **흐름**: 단계별 순서도 (코드 판정 → mini → 메인 모델 분기, 캐시 활용), 1회·하루 비용 상한.
5. **실패 처리**: 한도 초과, Telegram 오류(Forbidden·429·메시지 없음), 봇 권한 없음, 재시작 중 끊김, 중복 실행(동시 요청·버튼 연타), 대상 모호.
6. **보안**: 프롬프트 인젝션 시나리오 3개와 막는 지점, 오탐 시 되돌리는 방법.
7. **테스트 시나리오**: 정상 5개·권한 거절 3개·인젝션 3개·실패/경합 3개 — 각각 입력, 기대 결과, "고친 줄을 되돌리면 실패해야 하는" 확인 포인트.
8. **버튼 화면**: 1:1 메뉴와 방 카드 문구·버튼(callback_data 64바이트 이하).
한국어, 표와 목록 위주, 불확실한 건 `[가정]` 표시.
